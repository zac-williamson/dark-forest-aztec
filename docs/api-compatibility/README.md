# Contract fee reduction

This implementation changes storage and settlement for fresh games while retaining all 447 original contract methods, constructors and event schemas. It adds no player transaction or API argument. Existing game storage is not migrated.

| Complete transaction      | Original FJ | Optimized FJ | Reduction |
| ------------------------- | ----------: | -----------: | --------: |
| Move, no arrivals         |    8.432787 |     3.308645 |    60.76% |
| Refresh, no arrivals      |    4.165899 |     2.019898 |    51.51% |
| Find artifact, ordinary   |    5.650908 |     3.628879 |    35.78% |
| Move, 20 carried arrivals |   12.311938 |     8.491442 |    31.03% |

All 58 measured cases cost less than the original. These are complete local mock-network transactions with `proverEnabled:false`, normalized to the same [reference prices](../fee-benchmark/common-fee-schedule-provenance.md). They are not current live-network quotes and exclude deployment/setup costs. [Exact fees](v14-fee-evidence/fee-summary.json) and [paired state/event results](v14-fee-evidence/paired-transactions.json) are included. Some cases cost slightly more than earlier optimization candidates; the results report the combined implementation.

## Changes

- The original storage contracts retain authoritative roots, permissions and events. A shared Backend settles prepared updates through authenticated callbacks.
- Arrival payloads use lossless packing with a full-width fallback. Missing and explicitly stored zero states remain distinct.
- Core and Move avoid repeated calls and decoding. Unknown/custom stores retain the original call paths and ordering.
- Artifact updates can emit the original event without rewriting an unchanged root. Custom or aliased stores still receive both original setter calls.
- The vendored Aztec library reduces public argument decoding cost without changing wire encoding. Deployment and client artifact sync include the Backend and two workers.

Start with `contracts/state_backend/src/main.nr`, `contracts/system/core/src/main.nr`, `contracts/system/move/src/main.nr` and `contracts/system/artifact_valut/src/main.nr`. Storage source is generated by `tests/api-compatibility/generate_facades.py`; use the [maintainer instructions](../../tests/api-compatibility/README.md) when changing generated code.

## Install without generating proofs

Install the locked dependencies using Node 24.12.0 and pnpm 10.28.0. Download the native archive from the [prebuilt release](https://github.com/zac-williamson/dark-forest-aztec/releases/tag/v14-api-compatible-fees), verify its checksum and extract it to a separate directory. From the repository root:

```sh
python3 contracts/scripts/dev/api-compatible-build/publish.py --root . --native /path/to/extracted-native --check
python3 contracts/scripts/dev/api-compatible-build/publish.py --root . --native /path/to/extracted-native
pnpm --filter contracts codegen-contracts
pnpm --filter contracts copy-artifacts
pnpm --filter contracts scripts:typecheck
python3 tests/api-compatibility/check.py check --artifacts contracts/target/api-compatible --strict
python3 tests/api-compatibility/validate-selected-source.py --root .
```

This path authenticates 20 artifacts and 349 source inputs. It needs no Noir compiler, proof generation or verification-key cache. See the [build guide](../../contracts/scripts/dev/api-compatible-build/README.md) for rebuilding.

For a fresh local game, set `CONTRACTS_ENV_FILE` to a dedicated environment file with the local node, deployer and fee settings. Set `PROVER_ENABLED=false` for local proof-disabled testing, then run `deploy-contracts`, `configure` and `sync-env-and-artifacts` through `pnpm --filter contracts`. These commands do not implicitly rebuild. Use the newly deployed addresses; `configure` writes the default game configuration.

## Validation

The 447 original API checks, 58 paired fee/state/event cases, [381 targeted checks](v14-runtime-evidence/runtime-summary.json), [75 touch/custom-setter checks](v14-touch-runtime/summary.json), clean installation and deployment/client typechecks passed. Earlier V12 results remain historical. Fee runs used SDK/node 5.2.0 for both versions; build dependencies use SDK 5.0.1. Re-running fees on a fresh node requires preparing local fixtures.

No new proofs or verification keys were generated during final validation. Real-proof validation and browser/proving latency remain unmeasured. The baseline is repository commit `00bfa05c18862cce1c5adb362e4ecebe084c329a`; it is not an attestation of current deployed bytecode.
